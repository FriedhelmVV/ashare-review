# A股短线每日复盘工作台

一个自包含的 HTML 复盘工作台，按 **指数 → 趋势 → 情绪 → 题材 → 个股 → 消息面** 六个模块组织，
数据由同花顺 iFinD 接口自动取数生成，人工判断（主观情绪、周期阶段、题材逻辑、消息影响）在页面上填写并本地保存。

```
在线（任何设备、永久有效）：https://friedhelmvv.github.io/ashare-review/
本地（离线双击打开）：      ashare-review\复盘工作台.html
临时公网（换一台机器演示）：  双击 上线工作台.cmd
```

---

### 数据层 vs 标注层

这是本工作台的一个刻意设计：

```
data/2026-09-30.json         ← 机器取数层。tools/fetch.cjs 重跑会整体覆盖
data/2026-09-30.review.js    ← 标注层。你的判断，重跑不受影响
data/history.js              ← 多日序列层。区间问法一次拉多天，与单日文件互不覆盖
```

`manifest.js` 用 `review` 字段把前端引到标注层，**打开工作台就自动带出题材备注、消息批注、情绪分与阶段覆写**。

合并规则：某日**本地没有笔记**时，才用标注层文件初始化；一旦你在页面上改过，
就以本地为准不再被文件覆盖。**「复盘结论」这个 Tab 已按需求移除**（长文复盘请写在 `复盘/*.md` 里），
但标注层仍然加载——否则那 12 条题材备注和 3 条消息批注会从页面上消失。

`复盘工作台.html` 里内嵌了一份 **2026-09-30 的完整种子数据**（全天 8 项 KPI、20 个题材、56 只梯队、16 条带摘要的消息）
**外加 32 个交易日的历史序列**。所以**只拷走这一个 HTML 文件**、没有 `data/` 目录时，双击也能看到完整效果
（含「趋势」Tab）；一旦 `data/manifest.js` 存在，页面会自动改用真实数据，右上角徽标会从「内嵌种子数据」变成「data/ 目录」。
种子由 `build/build-seed.cjs --from-data data/2026-09-30.json` 生成；`build/inject-seed.cjs` 会同时把
`data/history.json` 注进 `<script id="rv-histseed">`。

## 二、页面构成

```
┌─ 顶栏 ────────────────────────────────────────────────┐
│  交易日下拉 (← → 方向键切换)   数据源徽标  载入JSON 导出 打印 │
├─ 概览（常驻，所有 Tab 都能看到）──────────────────────┤
│  ① 六大指数卡片（点位 / 涨跌幅 / 成交额）   ② 情绪温度计 │
│  ③ 8 个核心 KPI：涨停 / 跌停 / 最高连板 / 炸板率 /        │
│     涨跌家数 / 两市成交 / 晋级率 / 涨停成交               │
├─ Tab：指数 | 趋势 | 情绪 | 题材 | 个股 | 消息面 ──────────┤
└──────────────────────────────────────────────────────┘
```

### 模块一 · 指数
- **指数行情表**：六大指数（上证、深证成指、创业板指、科创50、中证1000、北证50）的收盘点位、涨跌幅、成交额及占比条。
- **量能与广度**：两市成交额（含环比）、上涨/下跌/涨停家数，以及涨跌家数分布条。
- 看什么：**指数是背景不是主角**。短线只关心三件事——两市成交额有没有放大、指数是普涨还是二八分化、下跌家数是否失控。指数涨但涨停家数萎缩，通常是权重护盘、题材退潮。

### 模块二 · 趋势（多日大盘变化）
数据来自 `data/history.js`（`tools/fetch-history.cjs` 用 `index_data` 的**区间问法**一次拉多日）。可切换**近 10 / 20 / 30 / 60 个交易日**。

1. **区间读数**：三大指数区间涨跌幅、日均两市成交、单日成交最高/最低、成交额首尾变化、上涨家数占优天数。
2. **指数累计涨跌幅**：以窗口首日收盘为 0%，三条折线（上证 / 深证成指 / 创业板指）叠加，直接看出谁在领涨领跌、分化何时开始。
3. **两市成交额与 5 日均线**：柱 + 虚线均线，量能的放大/萎缩一眼可见。
4. **涨跌家数**：红柱向上（上涨家数）、绿柱向下（下跌家数）的双向柱，**指数涨但绿柱更长 = 二八分化**。
5. **情绪温度**：涨停家数（柱）+ 情绪分（线）。这一块需要**逐日本地文件**（`data/<date>.json`），所以是随着每晚自动取数逐日累积的；03 个月前的历史行情有，但当时的涨停数据补不回来（`search_stocks` 配额已耗尽）。
6. **逐日明细表**：一天一行，含三大指数收盘与涨跌幅、两市成交与环比、上涨/下跌家数、涨停家数、情绪分。

看什么：**单日截图会骗人，趋势不会**。2026-09 这一段的读法——09-02 到 09-15 阴跌，成交额从 1.8 万亿缩到 1.5 万亿；09-17~09-22 指数反弹到 0% 附近但成交额没跟上；09-24 之后三大指数一起跳水，创业板指区间 −7.61% 明显弱于上证 −3.46%，而 09-30 那天上证收红 0.31%——**权重护盘 + 个股退潮**在趋势图上是一眼的事，只看看单日的红盘是看不出来的。

> ⚠️ 已知局限：`history` 里的成交额是**上证 + 深证成指**两家之和（与逐日 `index.totalAmount` 口径一致，已交叉验证吻合）；**休市日会被区间问法列出来**，落盘时按「涨跌幅为空」过滤，所以 `days` 里都是真交易日。

### 模块三 · 情绪
复盘的核心。包含四块：
1. **情绪分拆解**：把情绪拆成 6 个可量化分项（赚钱效应 / 涨停家数 / 连板高度 / 封板质量 / 晋级率 / 指数与量能），各自归一化后加权成 0~100 分。缺数据的分项自动剔除并重新归一化，不会当 0 处理。可用分项少于 3 个时不输出总分（只显示"数据不足"），否则单个分项会等价于大盘涨跌幅本身。
2. **连板梯队分布**：首板 / 2板 / 3板 …… 的家数柱状图，**空缺的层照样画出来**（虚线矮柱 +「断层 5板、6板」标注），健康的梯队是「金字塔」；头重脚轻意味着次日接力断档。
   > **「连板高度」分项按连续层数封顶**：有效高度 = `min(最高板, 连续层数+1)`。只看最高板会被孤峰骗到——2026-09-30 的 7 板中间断了 5、6 板，原口径给满分 100，封顶后是 66.7，总分从 60 降到 55（高潮→发酵），才和微观结构吻合。
3. **晋级率**：首板→2板、2板→3板、3板→4板、昨日涨停→今日连板的转化率。晋级率是接力资金意愿最直接的度量。
4. **数据体检**：列出当前还缺哪些字段、取数过程有哪些降级告警。这是「慢慢完善」的待办清单。

**情绪周期五阶段**（页面上自动判定，也可人工覆写）：

| 阶段 | 情绪分 | 特征 | 短线含义 |
|---|---|---|---|
| 冰点 | <20 | 亏钱效应主导，连板断层 | 等，不接刀 |
| 修复 | 20~40 | 亏钱效应收敛，首板增多 | 试错首板，小仓 |
| 发酵 | 40~60 | 主线成型，梯队健康 | 主升，做梯队 |
| 高潮 | 60~80 | 高度与家数双高 | 持股，不追高 |
| 退潮 | >80 且炸板率抬升 | 高位股补跌 | 减仓，只做反包 |

> 情绪分算法完整口径见 `SCHEMA.md` §7。

### 模块四 · 题材
- **题材强度排行**：按涨停家数排序，列出最高板、涨停股合计成交额、板块涨跌幅、代表个股。
- **题材梯队**：把当日涨停股按题材归堆，一眼看出哪个题材有连板梯队、哪个只有单点。
- **题材备注**：人工填写逻辑 / 持续性 / 龙头判断，自动保存。

看什么：**涨停家数只是入口，关键是梯队结构**——有 3 板龙头 + 多个 2 板跟风的题材才是主线；只有一堆首板的题材是脉冲。

> ⚠️ 已知局限：当前题材是**按同花顺一级行业**从涨停股聚合出来的，而短线语境里的「题材」≠ 行业。
> 比如「固态电池」「AI算力」这类跨行业题材，用行业归堆是看不出来的。
> 真正的题材归因要靠「涨停原因」，需要另接数据源或人工标注——这是后续最值得补的一块（见第五节第 6 条）。

### 模块五 · 个股
- **涨停梯队视图**（默认）：按板高分组的卡片墙，7连板 → 首板横向排开，卡片显示成交额、换手率、全市场成交额排名。
- **换手标识**：换手率 ≥10% 打「换手板」徽标（资金真金白银换手接筹），<2% 打「缩量板」徽标（筹码锁得住、但开板抛压集中）。**全市场成交额排名 ≤500 的标红加粗**，一眼分出「大资金票」和「小票缩量一字」。
- **涨停明细表**：可点表头排序（板高 / 成交额 / 换手率 / 名称），支持按代码、名称、行业搜索。
- **炸板股 / 跌停股 / 成交额榜**：三个补充清单。

看什么：成交额排名能区分「真金白银」和「缩量一字」；换手率能区分「换手板」和「一字板」。2026-09-30 的教科书例子——新华传媒 7 板但换手 1.34%、成交 1.45 亿、排名 2014（缩量一字）；襄阳轴承 4 板但换手 19.65%、成交 10.75 亿、排名 255（分歧换手）。**同为连板，完全不是一个性质**，卡片上的徽标让这个对比不用翻数据就能看见。

### 模块六 · 消息面
- 消息按热度排序，可按 **政策 / 产业 / 公司 / 海外 / 资金** 标签筛选。
- **正文摘要**：标题下面默认显示两行 `summary`（iFinD `资讯内容`，最多 200 字），点一下展开全文。政策细节、涨停原因往往只在正文里，光看标题是读不出来的。
- 每条可写「影响判断 / 对应题材」备注。
- 支持手工补录消息（iFinD 没覆盖到的，比如盘中突发）。
- 取数时已过滤广告软文（含「App是一款 / 下载App / 立即下载 / 扫码 / 开户」等字样的条目）。

看什么：消息面要和题材模块对照读——**有消息没资金（涨停家数没增加）是假题材，有资金没消息是资金抢跑**。

> 📌 **「复盘结论」Tab 已在本次改版中移除**（改为「趋势」）。长文复盘请写在 `复盘/YYYY-MM-DD-复盘.md`，
> 结构化复盘包用 `复盘/YYYY-MM-DD-复盘包.json` + `build/publish-review.cjs` 固化。
> 其中仍然有用的两块已搬进「情绪」Tab：**主观情绪打分滑块 / 情绪周期阶段覆写**（放在「数据体检」下方），
> 「数据体检与接口说明」本来就在那里。`data/<date>.review.js` 仍在加载，它现在只提供题材备注、消息批注与情绪覆写。

## 三、交互速查

| 操作 | 说明 |
|---|---|
| `←` `→` | 切换交易日（焦点不在输入框时） |
| 载入 JSON | 导入复盘包（`复盘/*.json`）或任意符合 `SCHEMA.md` 的 Day JSON |
| 导出 | 导出「Day 数据 + 人工笔记」为一个 JSON，可用于备份或跨设备迁移 |
| 按阶段看趋势 | 「趋势」Tab 里点近 10 / 20 / 30 日，切换观察窗口（选择会被记住） |
| 打印 | 打印时自动展开全部 Tab、隐藏按钮与区间切换条，A4 可直接存档 |

人工填写的内容保存在浏览器 `localStorage`（key `rv:notes:v1`），**不会回写 `data/`**。
换浏览器或清缓存会丢，重要结论请用「导出」备份，或用 `build/publish-review.cjs` 固化成标注层文件。

## 二·五、写一天的复盘（推荐流程）

```powershell
$node = 'C:\Users\p\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'
$ws   = 'D:\deepseek harness\ashare-review'

# 1) 先取数（见第四节）
& $node "$ws\tools\fetch.cjs" --date 2026-09-30

# 2) 在工作台里看数据、写复盘；写完点「导出」得到 复盘_2026-09-30.json

# 3) 把它发布成复盘层，之后打开工作台就自动显示
& $node "$ws\build\publish-review.cjs" "$ws\复盘\2026-09-30-复盘包.json"
```

复盘层和数据层是分开的文件，所以第 1 步重跑取数**不会冲掉**第 3 步发布的内容。

## 四、数据从哪来

数据由 `tools/fetch.cjs` 通过同花顺 iFinD MCP 接口抓取：

```powershell
# Node 不在 PATH，用内置运行时
$node = 'C:\Users\p\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'
$ws   = 'D:\deepseek harness\ashare-review'

# 正常取一天
& $node "$ws\tools\fetch.cjs" --date 2026-09-30

# search_stocks 配额用尽时，用本地 CSV 兜底提供涨停梯队
& $node "$ws\tools\fetch.cjs" --date 2026-09-30 --limitup-csv "D:\deepseek harness\涨停股_20260930.csv"

# 只重建 manifest.js，不发任何请求（手工改过 data/ 之后用）
& $node "$ws\tools\fetch.cjs" --manifest-only

# 增量刷新：只重取列出的模块，其余沿用 data/<date>.json 里已有的值
# search_stocks 配额已耗尽、跌停/炸板名单再也取不到时，这是安全刷新的唯一方式
& $node "$ws\tools\fetch.cjs" --date 2026-09-30 --only index,breadth,sector,news
```

| 参数 | 说明 |
|---|---|
| `--date YYYY-MM-DD` | 交易日，必填 |
| `--prev YYYY-MM-DD` | 手动指定上一交易日（默认按日历跳过周末推算） |
| `--limitup-csv FILE` | 涨停列表的本地 CSV 兜底源 |
| `--only MODS` | **增量取数**：只重取列出的模块，其余从已有 `data/<date>.json` 沿用 |
| `--sectors-all` | 抓全部 31 个申万一级行业的板块涨幅榜（写进 `sectors`），而不是只问有涨停股的行业 |
| `--no-sector` | 跳过板块涨跌幅（省配额） |
| `--no-prev` | 跳过上一交易日相关取数（省配额，代价是环比与晋级率留空） |
| `--manifest-only` | 只重建 `data/manifest.js`，不发请求 |

`--only` 可用的模块名：`index`（指数行情）、`limitup`（涨停/梯队）、`down`（跌停）、`broken`（炸板）、`breadth`（涨跌家数）、`topAmount`（成交额榜）、`sector`（板块涨幅）、`news`（消息面）、`prev`（上一交易日，用于环比与晋级率）。不写 `--only` 就是全量。

**为什么必须有 `--only`**：`search_stocks` 的配额是**账号级总量上限、不会每日重置**（2026-10-06 复查仍受限），全量重跑会把已经取到的跌停/炸板名单冲成空。增量模式还额外做了三件事：① 未重取的模块用旧值回填（含梯队、题材、核按钮、晋级率）；② 旧告警里与本次无关的照旧带过来，避免历史降级说明丢失；③ 上一轮的「本次为增量取数」说明会被替换而不是累积。

脚本会重写 `data/<date>.json` / `data/<date>.js` 并重建 `data/manifest.js`，刷新页面即可看到新的一天。
详细运行日志写在 `tools/last-run.log`（控制台只打 ASCII 摘要，避免 Windows 中文编码问题）。

### 4.0 多日序列（「趋势」Tab 的数据）

「趋势」Tab 画的是 `data/history.js`，由**另一个脚本**从 `index_data` 的**区间问法**一次拉回来：

```powershell
# 默认拉最近 40 个交易日，写到 data/history.json + data/history.js
& $node "$ws\tools\fetch-history.cjs"

# 指定结束日与天数
& $node "$ws\tools\fetch-history.cjs" --date 2026-09-30 --days 60
```

| 参数 | 说明 |
|---|---|
| `--date YYYY-MM-DD` | 序列的**结束日**（默认今天） |
| `--days N` | 往回取多少个交易日（默认 40） |
| `--out DIR` | 输出目录（默认 `data/`） |
| `--quiet` | 只输出结果摘要 |

它只问三样东西，**都不受 `search_stocks` 配额影响**：

1. `上证/深证成指/创业板指 …每日的收盘点位、涨跌幅、成交金额` —— **一个指数一次请求**（响应有长度上限，183 行会被截断成「以下为部分数据」）；
2. `沪深A股…每个交易日的上涨家数 / 下跌家数` —— 返回 `930903.CSI 中证A股` 的「指数成份上涨数量」，与逐日文件的 `breadth` 已交叉验证一致；
3. 两市成交额 = 上证成交金额 + 深证成指成交金额。

⚠️ 三个坑（都写进 `SCHEMA.md` §9 了）：

- **区间问法必须写「至」和「每日」**，否则拿到的是单日值；问「N 日成交额」拿到的是 **N 日累计**，问「成交额」拿到的是**区间成交额**——**必须写「成交金额」**。
- **休市日也会被列出来**（收盘价等于最近交易日、涨跌幅/成交金额为空），落盘时按「涨跌幅为空」过滤，所以 `days` 里都是真交易日。
- 成交额字符串可能是 `1.008万亿`——`toYi()` 早期只认「亿/万」，会把 **≥1 万亿的值静默清零**（已修）。

### 4.1 稳定性设计（都是踩坑换来的）

| 措施 | 原因 |
|---|---|
| **全部请求串行 + 间隔 2.5s，失败退避 10s/30s/60s** | 并发或连发会立刻触发 `HTTP 429 请求过于频繁` |
| **每项数据多套备选问法，空结果就换一种问法重试** | 同一问法会时而返回「查询结果为空」，空结果和报错一样致命 |
| **板块涨跌幅校验单日性** | 默认问法返回的是「截止日 52 周前」的**区间涨幅**，不是当日涨幅；必须显式限定起止日期同为当日，并在 `indicators_params` 校验 |
| **消息面只接受带 http(s) 链接的条目，并过滤提示文本** | `search_trending_news` 参数不合适时返回的是「使用提示 / 可能原因」文本，不校验就会当成新闻写进去 |
| **递归解字符串化 JSON** | `search_news` 把结果放在 `data.data`，而且是一个被 JSON 编码的**字符串**，不是 `data.result` |
| **每项独立 try/catch，取不到写 `null` + `warnings`** | 任何单项失败都不应让整天数据失败 |
| **`search_stocks` 的指标列必须逐列钉日期**（`成交额[20260929]`） | 不写日期后缀时，iFinD **按列**返回**最新交易日**的值：问 09-29 的「成交额 / 换手率 / 连续涨停天数」，涨停列对，另三列悄悄给成 10-08 的（实测万科A 的连续涨停天数 1 → 0、成交额错成 31.77 亿）。取值一律走 `colD(row, subs, date)` |
| **板块涨幅逐批重取：余数不能单独成批，重试必须换问法** | 批次里只剩 1 个行业时接口**必然**只回代码/简称、不回值；而且同一问法连续 4 次全失败、把批次从 5 个加到 6 个就 4/4 成功 —— 所以重试时要在问法末尾**追加一个行业**（`filler`），最多试 5 次 |
| **板块榜按行业名并集，不整体替换** | 一批随机失败会把上一轮拿到的行业抹掉（实测 31 → 26 → 16 个）。题材涨幅也必须从**并集之后**的榜单回填，否则「这批失败但上次有值」的行业会变成 `pct: null` |
| **陈旧告警只在「该模块本轮真的重取了」时才丢弃** | 否则补齐数据后页面还挂着「涨停梯队未取到」。用 `MISSING` 正则 + `byModule` 判定；纯来源说明（如「涨停梯队来自本地 CSV」）不含缺失词，必须保留 |

### 4.2 配额限制（重要）

iFinD 的**按工具**配额是真实的硬约束。实测把 `stock/search_stocks` 打到上限后，接口返回：

> 当前请求的 MCP 工具 `search_stocks` 已经达到用户账号权益下该工具请求次数上限……

此时 `index`（指数、板块）与 `news`（资讯）**仍然可用**，只有 `search_stocks` 相关的
涨停 / 跌停 / 炸板 / 成交额榜会返回空。表现为「接口 200 正常、结果为空」，很容易被误判成解析 bug。

⚠️ **它不是每日额度，不会次日重置**（2026-10-06 长假中复查仍受限），所以：

- 涨停梯队改用 `--limitup-csv` 从本地 CSV 补（或丢进 `inbox/`，让每晚的自动任务去补，见 4.4）；
- 跌停 / 炸板 / 成交额榜在配额耗尽后就**取不到**了，只能靠 `--only` 增量取数把已经拿到的旧值保住
  —— **绝对不要对已有数据的日子做全量重跑**。

**配额是可以充回来的**：2026-10-08 用户充值 iFinD 账号后 `search_stocks` 立刻恢复（探针问 09-29 涨停
返回 57 只），于是把 09-29 / 09-30 / 10-08 三天缺的涨停梯队、跌停、炸板、成交额榜、题材、核按钮、
分档晋级率全部补齐（见 §4.3）。**补历史日期时按天单独跑、并且从前到后（先补前一日，后一日才有
`--prev` 可用）**：

```powershell
& $node "$ws\tools\fetch.cjs" --date 2026-09-29 --prev 2026-09-28 --sectors-all --only limitup,down,broken,topAmount,sector,prev
& $node "$ws\tools\fetch.cjs" --date 2026-09-30 --prev 2026-09-29 --only prev,topAmount
& $node "$ws\tools\fetch.cjs" --date 2026-10-08 --prev 2026-09-30 --sectors-all --only limitup,down,broken,topAmount,sector,prev
```

⚠️ 对**已有 `amountRank`（全市场成交额排名）的日子**（09-30 来自本地 CSV）不要带 `limitup`，
否则那张榜会被接口重写成 `amountRank: null` —— 那个指标现在仍然取不到。

### 4.4 每晚自动更新（Windows 计划任务）

已经注册好一个计划任务，**交易日晚上 19:00 自动把当天的盘面数据写成 `data/<date>.json`**，
第二天打开工作台直接就能看到新的一天。

```
任务名：\A股短线复盘工作台-每日取数
触发 ：每周一至周五 19:00（StartWhenAvailable，错过会在开机后补跑）
执行 ：<内置 node.exe> "…\ashare-review\tools\daily-update.cjs" --catch-up
工作目录：D:\deepseek harness\ashare-review
失败重试：RestartOnFailure，失败后每 5 分钟重试，最多 3 次
超时  ：ExecutionTimeLimit = PT30M（卡死超过 30 分钟强制结束，不会挂到第二天）
```

**为什么要有 `--catch-up` + 失败重试**

2026-10-08 真的踩过一次：任务 19:00:00 准点启动、也正确判定出当天是交易日，
但进程在 `19:00:02` 被强制终止（计划任务「上次结果」= `-1073741510`，即 `0xC000013A`），
当天的数据没落盘。两道保险让它自己恢复：

- `--catch-up` 每次都会从「本地最后一天」往后补齐所有缺失的自然日 —— 所以就算某天全挂，
  下一次运行也会把那一天连同新的一天一起补上；
- `RestartOnFailure` 让被终止/失败的任务在 5 分钟后自动重跑。

同一晚还暴露出两个**只在真交易日才会走到**的 bug（休市那几天全被 `skip` 挡住，所以一直没暴露）：
`tools/daily-update.cjs:259` 与 `:277` 两处 `spawnSync` 多传了一个参数
（`spawnSync(node, [SCRIPT], ['--days', …], {options})` —— 第 3 个数组被 Node 当成 `options`，
抛 `ERR_INVALID_ARG_TYPE: The "options" argument must be of type object. Received an instance of Array`），
导致「刷新多日历史序列」和「自动发布到 GitHub Pages」两步全崩。已改为正确的三参数形式。

多日历史的窗口由 `tools/daily-update.cjs` 的 `HISTORY_DAYS` 控制，**单位是自然日**（不是交易日）：
`60` → 约 38~41 个交易日，足够喂满趋势页的「近 30 日」档。

管理命令：

```powershell
$node = 'C:\Users\p\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'
$ws   = 'D:\deepseek harness\ashare-review'

& $node "$ws\tools\schedule.cjs"               # 查看状态（下次运行时间、上次结果、最近逐日结果）
& $node "$ws\tools\schedule.cjs" --install     # 注册；已存在则覆盖。改时间：--time 19:30
& $node "$ws\tools\schedule.cjs" --uninstall   # 卸载
& $node "$ws\tools\schedule.cjs" --run         # 立刻手工触发一次（等于在任务计划程序里点「运行」）
```

只想手工跑一次、不碰计划任务：

```powershell
& $node "$ws\tools\daily-update.cjs"                 # 更新今天
& $node "$ws\tools\daily-update.cjs" --catch-up      # 顺带补上「本地最后一天→今天」之间漏掉的交易日
& $node "$ws\tools\daily-update.cjs" --date 2026-10-09
& $node "$ws\tools\daily-update.cjs" --dry-run       # 只打印将要执行的命令，不发请求
& $node "$ws\tools\daily-update.cjs" --force         # 跳过交易日判定（手工补数用）
```

它每晚按下面的顺序做决定：

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| 1 | 判断今天是不是交易日 | iFinD **没有交易日历工具**。而休市日问「今天上证收盘点位」**不报错**，会把上一交易日的收盘价原样返回，`indicators_params` 甚至谎报日期。可靠的办法是：**休市日返回的收盘价与上一交易日逐位相同**（指数 4 位小数，两天完全相同的概率可忽略）。周末直接判定、不发请求 |
| 2 | 该日 `data/<date>.json` **已存在** → 走 `--only index,breadth,sector,news` | 这是硬性要求不是优化：`search_stocks` 配额永久耗尽，全量重跑会把跌停/炸板名单冲成空（见 4.2）。缺的模块从旧文件继承 |
| 3 | 该日**不存在** → 全量取数 | 首次取数，能拿多少拿多少，取不到的写 `null` + `warnings` |
| 4 | 显式传 `--prev <本地最近的一个日期>` | `fetch.cjs` 自带的 `prevTradingDay()` 只跳周末、**不跳节假日**，长假后第一个交易日会算错环比基准 |
| 5 | 找 `inbox/涨停股_YYYYMMDD.csv` | 配额耗尽后补涨停梯队的唯一通道。有该文件、且当日梯队为空时，改用 `--only index,limitup,breadth,sector,news --limitup-csv …` 把梯队补进去 |
| 6 | `--sectors-all` 抓全部 31 个申万一级行业 | 这张榜取自 `sector_data`，**不受 `search_stocks` 配额影响**。所以哪怕某天一个涨停股都取不到，「题材」页也还有板块涨幅可看 |
| 7 | 当天真的取到数后，再跑一次 `tools/fetch-history.cjs --days 40` | 刷新 `data/history.*`，「趋势」Tab 自动多出今天这一根柱。失败只记日志，不影响当天成功判定 |

**怎么补涨停梯队**：把同花顺导出的涨停股表（列名见 `SCHEMA.md`）命名成 `涨停股_20260930.csv`，
丢进 `ashare-review\inbox\`，当晚的自动任务就会自动用它补上那天的梯队。放进 `ashare-review\`
或工作区根目录也能被找到，但 `inbox\` 最干净。

**长假不会白烧请求**：`daily-update.cjs` 会把「确定的非交易日」记进 `tools/known-days.json`，
所以国庆这种长假只有第一次会逐日探测，之后每晚都是秒回。
（只缓存「周末 / 收盘价逐位相同」这种确定结论；「接口异常取不到」绝不缓存，
否则一次网络抖动就会把当天永久误判成休市。）

**出问题先看哪**：`tools/daily-update.log`（每次运行追加，含 `fetch.cjs` 的完整进度输出）和
`tools/daily-update.state.json`（逐日结果）。`node tools/schedule.cjs` 会把这两者的摘要打出来。
任务本身跑没跑、返回码是多少，看它输出的「上次结果」（0 = 成功）。

### 4.5 上线（让手机等任何设备打开）

**双击 `上线工作台.cmd`** 就行（约 20 秒）。它会：

1. 起一个**只读**静态服务 `tools/serve.cjs`（默认 `127.0.0.1:8787`，被占自动往后挪）；
2. 通过 SSH 反向隧道映射到公网，拿到一个 `https://xxxx.lhr.life` 网址；
3. **从公网侧真的请求一次**，确认不是「隧道通了但服务没通」；
4. 把网址写进 `在线网址.txt` 并打印二维码（手机扫码即可打开）。

命令行等价用法：

```powershell
& $node "$ws\tools\online.cjs"                  # 一条命令上线（自动选通道）
& $node "$ws\tools\online.cjs" --via ssh        # 强制用 SSH 隧道
& $node "$ws\tools\online.cjs" --via cloudflared # 强制用 cloudflared（需先下载，见下）
& $node "$ws\tools\online.cjs" --port 8790      # 指定端口
& $node "$ws\tools\online.cjs" --no-tunnel      # 只要本机/局域网服务，不开公网
& $node "$ws\tools\online.cjs" --status         # 看当前网址、PID、公网自测
& $node "$ws\tools\online.cjs" --stop           # 关掉服务与隧道
```

| 通道 | 需要什么 | 网址形态 | 说明 |
|---|---|---|---|
| `ssh` | 系统自带 OpenSSH | `https://<随机>.lhr.life` | **默认可用、零安装**。先试 `nokey@localhost.run`，失败自动换 `serveo.net` |
| `cloudflared` | `tools/bin/cloudflared.exe` | `https://<随机>.trycloudflare.com` | **推荐，本机已装**（2026.10.0，51MB）。下载：`Invoke-WebRequest https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe -OutFile tools\bin\cloudflared.exe`。`--via auto` 装了它就优先用它 |

**URL 设计**：`/`、`/index.html`、`/workbench.html`、`/dashboard.html` 都指向 `复盘工作台.html`，
所以网址里不带中文，扫码/转发都不会乱码。

**六个坑（都踩过）**：

- **`-R` 必须写 `127.0.0.1` 而不是 `localhost`**。Windows 上 `localhost` 先解析成 IPv6 `::1`，
  而 `serve.cjs` 只监听 IPv4 → 隧道建好了、网址也拿到了，但请求永远进不来（表现为 502 /
  `curl: (52) Empty reply from server`，且 `tools/online-serve.log` 里**一条请求都没有**）。
  `-R 80:localhost:8787` 是错的，`-R 80:127.0.0.1:8787` 才对。
- **隧道商的欢迎语里也有 https 链接**（如 localhost.run 的 `https://admin.localhost.run/`），
  而且它也回 200，宽泛正则会把它当成隧道地址、自测还会「通过」。`online.cjs` 因此逐行匹配并
  跳过 `admin.localhost.run` / `localhost.run/docs` / `console.serveo` / `serveo.net/settings`。
- **自测不能只看状态码**，还要验身份：`isOurs(body)` 要求响应里同时含 `"ok": true` 和
  `复盘工作台.html`。
- **拿到 cloudflared 网址 ≠ 隧道已就绪**：它**先打印网址、再花几秒注册边缘连接**。所以要等日志里
  出现 `Registered tunnel connection` 再开始自测（`waitForLog`）。
- **新域名的 `getaddrinfo ENOTFOUND` 是 Windows 的否定缓存害的**（最阴的一个坑）。域名是隧道启动
  那一刻才发布的；在它发布**之前**查过一次，Windows 就会按 SOA 的否定 TTL 把 NXDOMAIN 缓存住好
  几分钟，之后所有查询都直接返回 ENOTFOUND —— 明明隧道已经好了，却连续失败 38 次、白等 75 秒。
  两条对策：注册成功后**静置 8 秒**再发第一个请求（不要自己制造那次 NXDOMAIN），以及自测里一旦
  看到 `ENOTFOUND`/`EAI_AGAIN` 就 `ipconfig /flushdns`（实测**不需要管理员权限**，exit=0）。
- **数据文件一律 `no-store`**，否则每晚 19:00 更新后手机看到的是缓存里的旧盘面。

顺带：`--via auto` 会**跨通道回退**（cloudflared 不通就自动改走 ssh），所以任何一条通道坏掉都还有救。

**手机 / 窄屏（<560px）**：工作台是按大屏设计的，但加了一条窄屏断点 —— 卡片改单列、
表格在卡片内横向滚动，所以 390px 的 iPhone 上**不会**出现整页左右滚动。
实测（同源 iframe 精确控制视口宽度）：

| 视口宽 | 修复前 scrollWidth | 修复后 |
| --- | --- | --- |
| 320px | 414 | 311 = 视口宽 ✓ |
| 360px | 414 | 351 = 视口宽 ✓ |
| 390px | 414 | 381 = 视口宽 ✓ |

（`--window-size=390` 在 Windows 上量不准：Chrome 窗口宽度下限约 491px，
所以量窄屏要用同源 iframe，媒体查询才会按 390px 计算。）

**安全与时效（务必知道）**：

- 服务**只允许 GET/HEAD**、不做目录列举、`..` 穿越已拦截（`/%2e%2e/...`、`/..%2f...` 均 404），
  但它**没有任何鉴权** —— 拿到网址的人都能看到这个工作台，所以别把网址发到公开场合。
- 隧道商的免费网址是**临时的**：断网、休眠、关掉进程都会失效，重开就是**新网址**
  （新的会覆盖 `在线网址.txt`）。
- 想让网址**固定不变**，见 4.6。

### 4.6 固定网址（GitHub Pages）

上一节那个 `trycloudflare.com` 网址每次启动都会变。要一个**永不变、电脑关了也能打开**的网址，
用 GitHub Pages 托管静态站点。**本项目已经上线了**：

```
https://friedhelmvv.github.io/ashare-review/
```

仓库：<https://github.com/FriedhelmVV/ashare-review>（公开）。
实测：首页 200 · 137,096 B、`data/history.js` 200 · 8,176 B，与本地逐字节一致；
无头 Chrome 渲染出来 153,998 B 的 PNG，和本地 `preview-2026-09-30.png` 完全相同。
`/tools/*`（含 `.gh-token`、`pages.json`）一律 404 —— 发布包根本不包含 `tools/`。

**如果要换到别的账号 / 重新部署（约 5 分钟）**

1. 注册 GitHub：<https://github.com/signup>
2. 创建令牌：<https://github.com/settings/tokens/new?scopes=repo&description=ashare-review-publish>
   - Expiration 选 **No expiration**；勾选 **`repo`** 整块（其他都不用勾）
   - 生成后复制 `ghp_` 开头那串
3. 在 `ashare-review\tools\` 下新建文本文件 `.gh-token`，把令牌粘进去（**只有这一行**）
   （参考 `tools\.gh-token.example`）。也可以改用环境变量 `GITHUB_TOKEN`。
   ⚠️ 用记事本保存时注意别变成 `.gh-token.txt` —— 实测踩过：Windows 会存成 `.gh-token.gh-token`。
4. **双击 `发布到固定网址.cmd`** —— 它会自动建仓库、开启 Pages、推送全部文件，并打印网址。
   首次构建约 15~60 秒，之后每次推送几十秒生效。

仓库名/分支写在 `tools/pages.json`（`{repo, branch, private}`），想改仓库名就改这里。

**之后每天自动**

`tools\daily-update.cjs`（每晚 19:00 的计划任务）在刷新完 `data/history.*` 之后会自动跑一次
`publish-pages.cjs`，把最新数据推上去。**没配令牌就静默跳过**；发布失败只写日志，
不会影响当天取数的成功判定。

命令行等价用法：

```powershell
& $node "$ws\tools\publish-pages.cjs" --init      # 首次：建仓库 + 开 Pages + 全量推送
& $node "$ws\tools\publish-pages.cjs"             # 增量推送（只提交内容变了的文件）
& $node "$ws\tools\publish-pages.cjs" --dry-run   # 只组包并算差异，不发任何请求
& $node "$ws\tools\publish-pages.cjs" --stage tmp\site   # 把发布包落到本地目录，预览用
```

**它是怎么工作的（几个刻意的设计）**

- **不依赖 git**：本机没装 git，所以用 GitHub 的 Contents API 直接提交文件（Node 内置 `fetch`，零依赖）。
- **按内容差异增量提交**：本地算 git blob 的 `SHA-1`（`'blob <len>\0' + content`），
  与远端 tree 里的 sha 比对，**内容没变就不发请求**——每晚大约 7 个文件、230KB，
  通常只有 `data/<今天>.js`、`data/history.js`、`data/manifest.js` 三个要传。
- **白名单组包**：只发布 `index.html`（= `复盘工作台.html`）、`data/*.js`、`README.md`、
  `.nojekyll`。**`tools/` 整个目录不上传**，所以 `.gh-token`、日志、计划任务脚本都不会外泄。
- **`--stage` 可本地验收**：把发布包落到一个目录，用
  `node tools\serve.cjs --root tmp\site --port 8805` 起个服务，就能在推之前确认它真的能打开
  （`serve.cjs` 的首页会在 `复盘工作台.html` 与 `index.html` 之间自动识别）。

**注意**

- **仓库是公开的**：GitHub Pages 在免费账号上只能从**公开仓库**发布。
  也就是说 `data/*.js` 里的盘面数据、以及 `data/<date>.review.js` 里**你写的复盘批注**，
  任何知道网址的人都能看到。要藏起来需要 GitHub Pro（私有仓库 Pages）或改用别的方案。
- 首次推送后 GitHub 需要约 1 分钟构建；之后每次推送通常几十秒生效。
- 令牌等价于账号写权限：别贴聊天窗口、别提交到仓库。撤销：<https://github.com/settings/tokens>。
